# BrickCraft V0.9.5.2 — géométries Studio spécifiques

Cette version s'appuie **sans changement** sur le renderer GPU V0.9.5.1 testé fluide en jeu.

## Pourquoi le château avait des formes incorrectes

Les 9 références `bl_...` du château ne figurent pas sous leur nom spécifique dans l'archive officielle `complete.zip`. Elles concernent 249 occurrences ; auparavant, le moteur leur substituait automatiquement la géométrie LDraw de base (`3004`, `24246`, `3941`, etc.). Cette substitution conservait les positions LDraw, mais perdait les variantes de forme et les décorations.

Le fichier Studio `.io` de l'utilisateur possède un `model2.ldr` avec les maillages correspondant exactement aux neuf références. Le supplément **optionnel** `studio_parts.zip` contient ces formes, extraites du `.io` fourni. LDrawLibrary le lit **en complément** de `complete.zip` sans remplacer les éléments officiels. Les textures PNG embarquées sont conservées pour une étape ultérieure, mais **elles ne sont pas encore affichées** (pas d'UV dans le renderer BrickCraft).

## Installation

- Fermer Minecraft ; sauvegarder le monde.
- Appliquer les sources V0.9.5.2 depuis la V0.9.5.1 et compiler.
- Double-cliquer `INSTALLER_PIECES_CHATEAU_WINDOWS.bat` depuis la racine du projet. Le fichier sera copié vers `run/config/brickcraft/studio_parts.zip` (avec sauvegarde du précédent s'il existe).
- Vérifier que `run/config/brickcraft/complete.zip` est toujours présent.
- **Redémarrer Minecraft** pour libérer les VBO de l'ancienne géométrie et reconstruire le cache. La projection `.bcpx`/NBT déjà enregistrée n'a pas besoin d'être réimportée.
- En installation Fabric classique, déposer `studio_parts.zip` dans le **config/brickcraft/** de l'instance Minecraft concernée à la place du répertoire `run/` du développement.
- Le supplément doit également être présent sur le serveur s'il initialise les mêmes modèles ; ne pas changer les sauvegardes existantes.

Pour un *autre* projet BrickLink, glisser son `.io` sur `EXTRAIRE_AUTRES_PIECES_IO_WINDOWS.bat`. Cela extrait les géométries `bl_` disponibles dans son `model2.ldr` et les ajoute au supplément existant.

## Diagnostic des rotations

Le mode de projection exacte existe déjà depuis la V0.9.1 : il ne limite pas les rotations aux quarts de tour. Les 3 245 pièces du château sont sauvegardées avec leur matrice LDraw 3×3 complète, sans conversion en angles Minecraft. Le test du château confirme leur validité et leur sauvegarde/relecture sans aucune différence. Les *830 orientations non orthogonales* signalées par le diagnostic historique décrivent les limites de l'ancien éditeur sur grille, **pas** un arrondi dans la projection précise.

**Limitations** : les triangles imprimés nécessitant une texture UV restent monochromes ; certaines zones du château peuvent donc être visuellement imparfaites. Les articulations arbitraires et positions fractionnaires ne sont toujours pas prises en charge par le moteur **BrickPiece/Studio classique** ni ses collisions. Il ne faut pas déclarer cette limitation résolue : la future édition libre reposera sur les coordonnées/matrices du modèle précis.
