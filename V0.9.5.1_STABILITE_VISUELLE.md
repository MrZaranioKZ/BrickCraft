# BrickCraft V0.9.5.1 — Correctif de visibilité GPU

**Correctif bêta, non validé en jeu.** Utiliser dans une **copie du monde** et conserver le JAR V0.9.4/0.9.5. Aucune modification du format BCPX ni de la sauvegarde des ancres.

## Pourquoi des LEGO disparaissaient

La V0.9.5 combine un filtre directionnel simplifié (`behindCamera`) et le tracé direct d'un `VertexBuffer` avec la seule matrice fournie au BlockEntityRenderer. Ce ne sont pas des garanties de visibilité ou de transformation de caméra correctes pour un VBO dessiné directement. Les screenshots révèlent des absences angulaires ; on ne peut isoler définitivement l'une de ces causes sans test en jeu.

## Modifications

- Filtre directionnel **OFF par défaut** : tous les lots spatiaux du château sont préparés puis dessinés indépendamment de la direction du regard.
- Nouvelle matrice de caméra explicite : `view = inverse(cameraRotation) * translate(anchor - cameraPosition)`. Les triangles restent définis relativement à l'ancre, comme en V0.9.5.
- Statistiques F9 : nombre de lots total/affichés, prêts, manquants, écartés, triangles et appels GPU.
- Comparaisons accessibles en jeu : `F6` alterne GPU / legacy (renderer visuellement stable mais lent), `F7` filtre OFF / ancien filtre, `F10` caméra explicite / ancienne matrice ; `F8` masque/affiche, `F9` stats.
- Les bascules F6/F7/F10 sont temporaires pour le diagnostic : le redémarrage restaure le fichier de configuration.
- Les erreurs Java du renderer GPU continuent à déclencher un fallback automatique vers legacy. Une erreur **purement visuelle** ne peut pas être détectée automatiquement ; F6 sert à ce cas.
- Les VBO persistent entre les images ; pas de retour aux 3 FPS attendu **tant que le GPU reste actif**, mais le résultat réel est à mesurer.

## Configuration (config/brickcraft/precise-render.properties)

```properties
gpu_render_mode=gpu
gpu_culling=off
gpu_view_matrix=explicit
gpu_mesh_quality=low
gpu_section_blocks=12
gpu_uploads_per_frame=2
gpu_max_memory_mb=192
```

Ces options sont compatibles avec un ancien fichier `.properties` : en absence de nouvelles clés, `off` et `explicit` s'appliquent automatiquement.

## Installation

1. Sauvegarder le monde, retirer l'ancien JAR du dossier mods.
2. Décompresser les sources complètes ou **appliquer le patch à la racine des sources V0.9.5**.
3. Lancer `TESTER_GPU_STABILITE_WINDOWS.bat` puis `CONSTRUIRE_WINDOWS.bat` (Java 21).
4. Lancer le client Fabric 1.21.1 avec le nouveau JAR et les géométries LDraw déjà installées.
5. Devant le château, presser F9 et attendre `manquants:0` ; comparer F6 en regardant une tour sous le même angle, puis revenir en GPU.
6. Si la géométrie s'affiche inversée ou décalée, essayer **F10** pour revenir à la matrice précédente ; envoyer une image F3 + F9 dans chacun des deux modes.
7. Si des lots disparaissent après F7, conserver le filtre OFF ; F7 active temporairement l'ancien calcul pour démontrer l'anomalie.

**Contrôle important :** `manquants > 0` pendant les premières images est normal (`gpu_uploads_per_frame`), mais un compteur bloqué en permanence peut indiquer une insuffisance de mémoire GPU ou une erreur de géométrie.

La compilation en Java contre classes de substitution valide la structure source mais **ne constitue pas** une compilation complète Gradle/Fabric ni un essai graphique réel.
