# BrickCraft V0.20.0 — Onglet créatif, commandes et copies de briques

Minecraft / Fabric : **1.21.1**. Cette archive contient les **sources** du mod (pas un JAR compilé).

## 1. Onglet de l'inventaire créatif

Un onglet « BrickCraft | Briques & outils » est inscrit dans l'inventaire créatif natif.
Il regroupe :

- l'outil BrickCraft (`brickcraft:builder_wand`) ;
- la pièce générique LDraw (`brickcraft:ldraw_part`) ;
- toutes les briques classiques, plaques, tuiles et pentes déjà présentes dans le mod.

Glisser les pièces dans la barre rapide, puis clic droit sur un bloc pour les poser.
`N` ouvre toujours le catalogue détaillé LDraw/couleurs ; `C` change de couleur ; `R` tourne ; `G` modifie le pas de rotation ; `B` ouvre le Studio.
Les milliers de références LDraw ne sont volontairement **pas** ajoutées toutes à l'inventaire créatif, pour éviter un inventaire énorme et lent : on les sélectionne avec `N` ou on en obtient une par commande.

## 2. Commandes de pose (serveur / autorité OP niveau 2)

| Commande | Exemple |
|---|---|
| Liste des pièces classiques | `/brickcraft list` |
| Aide | `/brickcraft help` |
| Poser une brique classique | `/brickcraft place brick_2x4 ~ ~ ~` |
| Poser avec couleur et orientation | `/brickcraft place brick_2x4 ~ ~ ~ rouge 90` |
| Poser une pièce LDraw | `/brickcraft ldraw 4079 ~ ~ ~` |
| Poser une pièce LDraw colorée | `/brickcraft ldraw 4079 ~ ~ ~ 0xC42830 90` |
| Recevoir un objet LDraw identifié | `/brickcraft give 4079 16` |

- Les coordonnées `<x y z>` utilisent l'argument Minecraft natif : absolues, `~` relatives, etc.
- Une rotation `90` correspond à 90° autour de l'axe Y, y compris pour les pièces LDraw.
- Les couleurs sont des noms français/anglais (`blanc`, `noir`, `rouge`, `red`, etc.), `0xRRGGBB`, un entier décimal, ou `"#RRGGBB"` avec guillemets.
- Les commandes sont exécutées par le serveur, compatibles avec `/execute`, les fonctions `.mcfunction` et les blocs de commande autorisés.
- Les placements sont refusés si le terrain est occupé, si le chunk n'est pas chargé, si une protection interdit la modification, si une pièce est invalide ou si elle occupe plus de 256 cellules Minecraft. Les opérations sont validées avant toute modification.
- Une référence LDraw doit être installée dans les bibliothèques sur les machines qui l'utilisent et avoir une géométrie disponible.
- `give` réserve la référence de la pièce dans `minecraft:custom_data` de l'objet. Prendre cet objet dans la main active automatiquement la référence correcte, sans la rechoisir dans le catalogue.

## 3. WorldEdit et Axiom — copie de cellules physiques

Les cellules classiques `brickcraft:cell` stockaient autrefois les coordonnées **absolues** de toutes les pièces qu'elles contenaient.
Dans la V0.20, le NBT `PiecesV2` stocke des coordonnées **relatives à chaque cellule** (`RelativeV20=true`), avec X/Z en blocs et Y en unités LEGO (1/5 bloc).
La lecture des anciens NBT reste prise en charge : ils sont convertis lors de la sauvegarde sous la nouvelle version.

Les outils qui copient **le bloc + les données NBT de son BlockEntity** (comme le presse-papier WorldEdit ou les schematics Axiom qui conservent le NBT) peuvent donc translater les cellules BrickCraft sans conserver les anciennes positions absolues. Il faut sélectionner TOUTES les cellules d'une pièce multi-blocs, pas seulement une moitié.

**Limites importantes :**

- `//set brickcraft:cell` crée une cellule sans modèle de pièce. Une forme LEGO nécessite sa donnée NBT ou une commande `/brickcraft place`.
- La copie/collage par translation est préparée, mais le comportement dépend des versions exactes de WorldEdit/Axiom : **intégration en jeu non validée**.
- Les rotations/mirrors du clipboard ne réorientent pas automatiquement les matrices internes des pièces ; ce n'est pas encore une compatibilité complète de transformation.
- Les grandes projections GPU `brickcraft:precise_display`, avec leurs collisions séparées, n'utilisent pas ce même chemin de copie. Les commandes ci-dessus placent des pièces *classiques/LDRAW dans des cellules*, et non une projection de milliers de pièces.
- Utiliser une copie du monde pour tester WorldEdit/Axiom. Ne pas coller sur un projet précieux sans sauvegarde.

## 4. Installation / vérifications

1. Décompresse le ZIP dans un nouveau dossier (ne mélange pas avec les anciennes sources).
2. Lance `TESTER_CREATIF_COMMANDES_V020_WINDOWS.bat` pour les tests Java autonomes.
3. Lance `CONSTRUIRE_WINDOWS.bat` pour construire le JAR Fabric via Gradle/Loom, puis remplace l'ancien JAR de BrickCraft dans `mods`.
4. Lance Minecraft, ouvre l'inventaire créatif, puis essaye la commande `/brickcraft place brick_2x4 ~ ~ ~ rouge 90`.
5. Dans un monde de test, pose quelques briques, sélectionne toutes leurs cellules avec WorldEdit, puis teste `//copy`, `//paste` et un rechargement du monde.

**Tests réalisés** : tests autonomes des couleurs et coordonnées relatives ; tests de régression V0.17 grands modèles et V0.19 suppression des pièces manquantes ; intégrité ZIP.
**À réaliser sur le PC de l'utilisateur** : compilation Fabric complète, lancement du jeu, tests réels de WorldEdit/Axiom et rendu dans l'inventaire.
